### E271: Option declared twice in one list

The same option identifier appears twice in one `(…)` list. Dynare refuses: `option {name} declared twice`. The `external_function` list accepts repeats and keeps the first value. The adjacent option lists of `mshocks` and `shock_paths` use Dynare's other sentence: `The '{name}' option is declared multiple times`.

**Warrant**

When Dynare prints an internal prefix such as `initial_condition_decomp.type` or `plot_shock_decomp.fig_name`, the editor names the option as written: `type` or `fig_name`.

**Fix**

Keep one copy of that option in the list.
